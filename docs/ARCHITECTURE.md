# 架构与数据安全

世界目录 `prefablitematica/blueprints/`：

```text
<UUID>.bprint   gzip 压缩结构：尺寸、相对坐标、完整状态、流体标识、清洗后的 BlockEntity
<UUID>.json     服务端材料需求、充能进度、锁定状态、停用状态
```

蓝图 ItemStack 只存 UUID、名称、旋转和方块数量等小型显示数据。FluidState 的全部属性由原始 BlockState（包含 level 和 waterlogged）恢复，并验证传输的流体 ID 与状态一致。结构文件与进度文件分开，充能不重写大型建筑。

网络每片最大 24 KiB，逐片确认；全服至多两个上传/分析会话；未活动上传 60 秒过期。服务端检查压缩和解压大小、UTF-8、尺寸、数量、重复坐标、注册 ID、全部属性及属性值、流体一致性、NBT 大小和深度。客户端不能提供最终材料分类、进度、UUID 或实体数据。

BlockEntity 使用保守的白名单：容器为空，移除所有库存、战利品和组件数据；保留告示牌文本/颜色及旗帜图案等装饰信息，删除命令点击行为。客户端导出时过滤 Litematica 方块实体表中的失效条目，并在传输前移除容器物品，避免普通库存占满 NBT 限额。服务端仍严格拒绝外部数据中与方块不匹配的 NBT 或 BlockEntity ID。其他 BlockEntity 仅保留方块，初始化为默认空状态。`forbidden_blocks` Tag 禁止命令方块、刷怪笼、结构方块、移动活塞等技术方块和工程台自身。

充能时先消耗材料并返还空桶及潜影盒，将工程台所在世界的区块数据和玩家库存保存到磁盘，再原子保存充能进度。这一步有同步存盘成本，但避免重启后材料和充能同时保留。

放置按 Tick 验证整个范围、预计算旋转后的结构及支撑关系，然后分阶段放置主体、重力/依赖方块、BlockEntity、waterlogged、水与气泡柱、岩浆、火焰和邻居/流体更新。临时区块 Ticket 不持久化，任务结束即释放。范围预留期间阻止外部修改、挖掘、爆炸掉落和流体/方块定时 Tick，蓝图 UUID 同时锁定。

**放置开始前持久化将充能扣到零**。预检失败不改世界、也不消耗充能。已经开始落块后若异常或强制结束进程，可能留下部分建筑，充能不退款、不自动回滚；这是为了避免恢复进度后重复生成。重启读取残留锁时会清理锁并保持零充能。

领地模组可注册 `PlacementValidator.ALLOW`，对包围盒内每个坐标做额外权限检查。没有注册回调的第三方领地规则不会自动集成。
